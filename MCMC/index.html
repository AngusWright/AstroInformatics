Model and sampler settings
Simulated observations

A seed fixes the data as well as the chains. Changing sampler settings keeps the same simulated observations.

Prior ranges

Gaussian priors are centred on each range midpoint, with SD = range width / 4, truncated to that range. N uses the corresponding discrete prior on integers. Zero is excluded for shapes and rates.

Sampler

Chains start at reproducible, dispersed valid points within the prior. All proposal parameters stay fixed: there is no adaptation.

Diagnostics and display

These controls never resample. Rejected attempts count as iterations and repeated states remain in the diagnostics.

ACFs are computed within each chain and averaged, never across concatenated chain boundaries. Constant chains have undefined ACF. Split R̂ needs at least two chains with four retained states each; a value near 1 is not proof of convergence. The simple ACF-based ESS truncates at 40 retained lags and can overstate information for slowly mixing chains.

A Metropolis–Hastings iteration

  1. Start at x with finite positive posterior density π(x).
  2. Propose y from q(y | x), even when it falls outside the target support.
  3. Compute the acceptance probability using both proposal directions.
  4. Draw U uniformly in (0, 1). Accept y if log U < log α; otherwise keep x. Record one state either way.
log r = log π(y) − log π(x)
      + log q(x | y) − log q(y | x)
log α = min(0, log r)
x[t+1] = y if log U < log α, otherwise x[t]

The unknown posterior normalising constant cancels. Log densities avoid underflow. An out-of-support proposal has log π(y) = −∞ and is rejected, not clipped, reflected or repeatedly redrawn.

The selected model

Proposal families

  • Gaussian random walk: independent N(0, s²) increments in both coordinates. For the Binomial model, N instead moves by −1, 0 or +1 with equal probability. These proposals are symmetric; their ratio cancels, including at the support boundaries because invalid moves are rejected.
  • Independent global: continuous coordinates are drawn from Gaussians centred at prior midpoints, with SD = range width / 3. N is drawn uniformly over all prior integers. The forward and reverse densities generally differ.
  • Mixture: select the global proposal with probability w, otherwise the local random walk. The Hastings ratio uses the full mixture density in both directions, not only the selected component. This is a proposal mixture, not a mixture target.

Try these experiments

  1. Compare tiny and large local proposal SDs. High acceptance can mean tiny, highly correlated moves; very large steps can leave long repeated-state plateaus.
  2. For Gaussian data, increase correlation. A spherical proposal struggles along a narrow diagonal posterior even when every density evaluation is correct.
  3. Use Binomial data. N must stay integer and at least the largest observed count; a boundary attempt is rejected rather than silently rounded back into support.
  4. Compare chains, then adjust burn-in and thinning without changing the cached trajectories. Different starts can reveal lack of exploration that one smooth-looking trace hides.
  5. Try a local/global proposal mixture. Better travel is possible, but global proposals are not accepted automatically; their proposal-density ratio matters.

Reproducibility and limits

Differences from the historical R app: its Gaussian-prior menu option was unimplemented and stopped with an error; here it means the explicitly bounded Gaussian prior described in the settings, not an unbounded normal prior. For non-Binomial models, R passed the control labelled “SD” as a covariance diagonal (variance). Here s consistently means proposal SD, so the covariance is s²I. The Binomial probability proposal already used SD in R and is unchanged.

Playback starts paused. All chains and all acceptance decisions are cached using a local seeded generator. Play, pause, next, rewind, seek and display changes reveal exactly the same run. Model or sampler changes regenerate the run. The data use a separate seeded stream, so changing proposal settings leaves observations unchanged. JavaScript and R random generators differ: equal seeds do not imply identical paths across languages.

The scale is fixed for the entire chain. Naively adapting proposals from the current sampling history can invalidate stationary-distribution arguments; any warm-up adaptation would need an explicit valid scheme and must not be mistaken for retained stationary sampling. No adaptation is performed here.

This demonstration infers two parameters from simulated observations; it is not an optimiser or a production convergence guarantee. The Gaussian data covariance is known. Gamma uses rate, not scale. Bounded priors define the target, so moving their bounds can legitimately change inference.
